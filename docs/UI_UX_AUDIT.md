# UX-аудит административной панели

Дата аудита: 2026-11-02. Область: React-приложение под `/admin/`; публичный runtime не переделывался.

## Исходная браузерная матрица

Админ-превью: `http://127.0.0.1:25463/admin/`, одноразовый локальный backend. Для маршрутов использованы чистые страницы, отсутствующая заявка и отсутствующий feature ID. Никакие сохранения, импорты, отзыва токенов, публикации, развёртывания, удаления или production API-вызовы из UI не запускались. Тестовые изменения формы существовали только в состоянии браузера.

| Измерение | Результат до исправлений |
| --- | --- |
| Маршруты и размеры | 24 адреса/состояния × 7 ширин = 168 проверок в тёмной теме: 360, 390, 768, 1024, 1280, 1440, 1920 CSS px. Одно горизонтальное переполнение: `/admin/access/users` на 360px, `scrollWidth=349`, `clientWidth=345`. Остальные комбинации прошли без горизонтального переполнения. |
| Свёрнутая навигация | На desktop активный пункт измерен как 36×36px, центр отличается от центра панели на 0.5px; разделители категорий видны. В мобильном размере sidebar заменяется меню-кнопкой. |
| Бренд и дубли | Название «Слой» и знак есть в навигации; в оболочке одна кнопка выхода, одна кнопка темы, отдельного профиля/поповера нет. |
| Ошибка и пустые данные | Пустые медиатека, заявки и реестр фич отображают действия; неизвестная заявка показывает ошибку, ID запроса, повтор и возврат к списку. Реальных feature-схем и записей нет. |
| Вход | Для изолированного анонимного origin показан экран входа. Отправка пустой формы показывает «Введите Bearer-токен» и не отправляет токен/API-запрос. Проверка валидного и невалидного секрета не выполнялась. |
| Раздел моделей данных | Не найден в навигации, DOM и маршрутах; `/admin/features` ведёт в контент, `/admin/features/new` — в реестр сборок. |
| Ограничения сценариев | Экран запрета доступа проверен по реализации/role guard; отдельный токен роли user не создавался. Touch-device эмуляции и полного заполненного набора записей в доступном preview не было. |

Пути сверены с `frontend/src/app/router.tsx`; доступы к site/access/settings по-прежнему ограничены существующим `RequireSiteManager` и серверными правилами.

| Раздел | Экраны |
| --- | --- |
| Сессия и ошибки | `/admin/login`, экран запрета доступа, неизвестный маршрут |
| Обзор | `/admin/` |

## Продуктовые ограничения

- Схемы контента принадлежат разработчикам фич, задаются в `manifest.json` и приходят с ZIP-сборкой. Ручной экран создания моделей данных не добавлять.
- Снапшот фиксирует сохранённую конфигурацию сайта и сохранённый редакционный контент; число версий не ограничено. Любой выбранный снимок можно развернуть независимо в `dev` или `production`.
- В редакторе дизайн-системы нет предпросмотра. Токены публичного сайта не управляют темой админки.
- Поверхности интерфейса остаются монохромными; цвет используется для успеха, ошибки, предупреждения и процесса.
- API-контракты, role/`can*` проверки, revision checks и безопасные действия сохраняются. Любые браузерные проверки записывают состояние только в одноразовый backend или локальный draft.

## Итоги после исправлений

| Эвристика | Итог и проверяемое поведение |
| --- | --- |
| 1. Видимость состояния | Состояния загрузки, сохранения и ошибки показывают актуальное действие: повторить чтение, сохранить или загрузить ревизию. Активные `dev`/`production` ревизии остаются видны на экране снапшотов. |
| 2. Соответствие реальному миру | Убран жаргон «принципал» из доступов. Права описываются через роль, а модели контента задаются манифестом фичи и не редактируются вручную в админке. |
| 3. Контроль и свобода | Изменение метаданных, настроек среды, страниц и маршрутов предупреждает о локальных несохранённых данных. Диалог оставляет выбор остаться или покинуть экран; конфликт не затирает локальные поля автоматически. |
| 4. Последовательность и стандарты | Развёртывание в production требует подтверждения. Сохранены серверные проверки ролей и ревизий. |
| 5. Предотвращение ошибок | Production-блокировка видна при несохранённых метаданных или нулевой dev-ревизии. Действия пользователей переносятся на мобильную ширину; повторная матрица не нашла горизонтального переполнения. |
| 6. Узнавание вместо запоминания | История показывает текущие версии и назначение снапшота. Любой выбранный снимок можно отправить отдельно в dev или production. Новые снапшоты включают сохранённый редакционный контент. |
| 7. Гибкость и эффективность | Поиск, фильтры, пагинация и работа с коллекциями сохранены. В доступной тестовой базе нет большого набора реального контента, поэтому массовая производительность не оценивалась. |
| 8. Эстетика и минимализм | Админка использует монохромные поверхности с цветом только для состояний. Удалён preview из редактора дизайн-системы; постоянная подсказка canvas заменена кнопкой справки. Уменьшены повторяющиеся пояснения и вложенные карточки. |
| 9. Распознавание и восстановление ошибок | Для загрузок добавлен повтор. Конфликт среды предлагает явно перезагрузить ревизию, сохраняя локальные значения до выбора пользователя. |
| 10. Справка и документация | Подсказка раздела использует один Tooltip для наведения, клавиатурного фокуса и нажатия. Общий компонент ограничивает ширину/высоту viewport и учитывает столкновения с границами. На мобильной ширине подсказка заголовка располагается над ним и не закрывает меню или вкладки. |

## Финальная responsive-матрица

Проверены те же 24 маршрута и состояния после изменений: `24 × 7 = 168` переходов в тёмной теме при 360, 390, 768, 1024, 1280, 1440 и 1920 CSS px. Все 168 замеров завершились без горизонтального переполнения. Включены экран входа в уже авторизованном тестовом контексте (переход на обзор), пустые/обычные экраны, отсутствующие submission и feature ID, редакторы, доступы, настройки и неизвестный маршрут.

Всплывающая справка отдельно проверена на 320, 360 и 390 px, а также в редакторе маршрутов на 320×568 px. У подсказки дизайн-системы минимальный боковой отступ — 8 px; она не пересекается с кнопкой мобильного меню, заголовком или списком вкладок. При 1024 px Tooltip свёрнутой навигации остаётся в границах viewport. Нажатие, наведение, Escape и клавиатурный фокус открывают и закрывают один визуальный Tooltip. Эмуляция физического сенсорного устройства отдельно не выполнялась.

Финальные viewport-скриншоты сохранены в `artifacts/ui-audit-final/`: дизайн-система на desktop и mobile, тот же редактор с Tooltip на обеих ширинах, canvas маршрутов с мобильной справкой, а также снапшоты на desktop и mobile.
