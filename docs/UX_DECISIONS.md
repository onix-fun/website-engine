# UX-решения и компромиссы

Дата: 2026-11-02.

## Информационная архитектура

- «Контент» объединяет работу с записями, файлами и заявками.
- Схемы записей задаются манифестами фич и загружаются вместе с ZIP-сборкой. Редакторы работают с готовыми записями в разделе «Контент»; ручного раздела моделей данных в админке нет.
- Параметры сайта, страницы и маршруты, сборки, дизайн-система и снапшоты находятся в разделе «Сайт».
- Доступы и системные параметры сгруппированы в «Администрирование».
- Учётная запись не дублируется в оболочке; внизу боковой панели остаётся действие выхода.
- Мобильная навигация остаётся доступным диалогом; активный пункт и свёрнутое состояние панели сохраняются.

## Визуальный слой админки

- Основные поверхности, навигация, кнопки, границы и активные элементы используют белые, серые и чёрные оттенки в обеих темах.
- Цвет зарезервирован за состояниями: зелёный означает успех, красный — ошибку, жёлтый — несохранённые изменения, предупреждение или текущий процесс. Информационные подсказки остаются нейтрально-серыми.
- Радиусы общих поверхностей увеличены; повторяющиеся поля токенов и раскрываемые настройки страниц показываются как строки, чтобы избежать карточек внутри карточек.
- Контекстная справка использует один общий Tooltip для мыши, клавиатуры и нажатия. Ширина, высота и положение ограничиваются viewport; в мобильном заголовке подсказка открывается над заголовком, не закрывая меню и вкладки.
- Публичный сайт и его дизайн-токены не перекрашиваются этим изменением; монохромная палитра относится к интерфейсу администрирования.

## Дизайн-система сайта

Редактор организован по категориям: цвета, типографика, размеры и сетка, радиусы и границы, эффекты, шрифты и бренд. Предпросмотр из редактора удалён по просьбе владельца продукта: настройки редактируются отдельно и вступают в силу после создания и развёртывания снапшота. CSP и старые API предпросмотра не менялись.

Числовые токены показывают отдельную единицу измерения; функции CSS вроде `clamp()` и `min()` сохраняются как целые выражения. Для цвета остаётся текстовое CSS-поле, а вспомогательные controls распознают HEX, RGB и HSL.

## Снапшоты и публикация контента

- Снапшот — неизменяемая копия сохранённого черновика конфигурации и контента.
- Можно создавать неограниченное число снапшотов, в том числе с одинаковым digest. Создание не меняет активное окружение.
- Любой выбранный снапшот можно отправить сразу в dev или production; окружения переключаются независимо. Старые действия promote/rollback сохранены для совместимости.
- Снапшот включает сохранённый черновик редакционной записи, если он есть; иначе — опубликованную версию dev, а при её отсутствии production. Порядок записей коллекции тоже закрепляется.
- Ответы и заявки форм не входят в снапшот: они остаются операционными данными и не теряются при переключении версии сайта.
- Старые снапшоты продолжают разворачиваться с прежней семантикой через версионированный payload.

## Состояние изменений

Перед созданием снапшота несохранённые изменения страниц и маршрутов предлагается сохранить. Конфликт ревизии показывает отдельное действие загрузки актуального черновика. Редактор дизайн-системы показывает состояние и номер ревизии, поддерживает сброс токенов, обработку конфликтов и предупреждает о несохранённых правках при навигации.

## Границы

Существующие API действий с контентом, сборками, медиа, доступами и настройками сохранены. Новые API снапшотов отражены в `docs/API.md`. Автоматическая полная проверка WCAG 2.2 AA и нагрузочные измерения не выполнялись; подробные ограничения перечислены в `docs/QA_REPORT.md`.
